Step 51→61之间发生了**相变**：low_var比例从9.4%暴增至85.9%。

### 2.3 崩溃因果链

```
1. BOK-GRPO集中advantage到top-K样本 → 更强的正向梯度信号
         ↓
2. kl_coef=0.01 (5x弱于GRPO) → KL正则化不足以约束大步长策略更新
         ↓
3. kl_loss从0.006→0.122 (20x增长) → 策略已经大幅偏离参考模型
         ↓
4. entropy从0.49→0.58 → 模型输出变得更随机、更不确定
         ↓
5. Format能力破坏：JSON key名损坏("point_2d"→"point_274.2")、丢失XML标签
         ↓
6. format_rejection=1：format失败→overall reward=0
         ↓
7. DAPO_FILTER=1：全组reward=0 → group_std=0 → DAPO过滤掉 → 零梯度
         ↓
8. 无纠正信号 → 更多format失败 → 更多被过滤 → 正反馈死螺旋
```

## 三、关键参数问题分析

### 3.1 KL系数问题（最关键）

| 指标 | GRPO (kl_coef=0.05) | BOK (kl_coef=0.01) | 分析 |
|------|---------------------|---------------------|------|
| kl_loss范围 | [0.003, 0.045] | [0.006, **0.448**] | BOK KL失控 |
| entropy范围 | [0.48, 0.52] | [0.49, **0.75**] | BOK entropy发散 |
| kl_loss贡献(pg_loss) | kl*0.05=0.001 | kl*0.01=0.0045 | 即使BOK kl更大，kl_loss项仍小 |

**核心问题**：`kl_coef=0.01`时，即使kl_loss到了0.448（巨大的策略偏移），对pg_loss的贡献仅`0.448*0.01=0.00448`，远小于pg_loss本身(0.01-0.03)。KL正则化形同虚设。

**GRPO对比**：kl_coef=0.05时，kl_loss=0.02就贡献`0.02*0.05=0.001`，足以在策略刚开始偏移时产生有效约束。

### 3.2 Clip参数分析

两个实验的pg_clipfrac_lower和pg_clipfrac_higher在所有步都是0.0，说明：
- **当前clip_ratio_low/high设置过宽**，ratio几乎从不被clip
- 原因：ppo_epochs=1(仅更新1次)，策略每步变化很小
- clip参数目前不是瓶颈，暂无需调整

### 3.3 BOK-GRPO Advantage机制问题

BOK-GRPO的advantage通过softmax温度τ集中在top-K样本上：
- **正面效应**：Steps 1-50期间，focused gradient让answer从0.815提升到0.792(comparable to GRPO)
- **副作用**：集中的advantage + 弱KL = 更快的策略偏移
- **adv_max=3.0 (bok_clip)**：最大advantage值被裁剪到3.0，这限制了单步最大更新
- **adv_min≈-0.9**：负advantage较小，意味着对"坏样本"的惩罚信号弱于GRPO(-3.75)

## 五、参数修改建议

### 5.1 下一次BOK-GRPO实验（已修改/待修改）

| 参数 | 旧值 | 新值 | 原因 | 状态 |
|------|------|------|------|------|
| BOK_DAPO_FILTER | 1 | **0** | 防止死螺旋 | ✅ 已修改(脚本默认) |
| BOK_TAU_FINAL | 0.3 | **0.5** | 防止过度选择 | ✅ 已修改 |
| kl_coef | 0.01 | **0.05** | 匹配GRPO正则化强度 | ❌ **需在启动命令中移除覆盖** |
| BOK_CLIP | 3.0 | **2.0** | 限制最大advantage | ⚠️ 建议修改 |
| Safety监控 | 无 | 已添加 | 自动告警和DAPO降级 | ✅ 已修改(core_algos.py) |

### 5.2 关键修改：kl_coef

**上次BOK-GRPO启动命令中必须有覆盖了kl_coef=0.01**（脚本默认是5e-2）。下次启动时：
- 不要覆盖kl_coef，使用脚本默认的`algorithm.kl_coef=5e-2`
- 或者如果需要BOK-GRPO稍微更自由的探索，可以设为`0.03`

### 5.3 可选优化

1. **BOK_CLIP降低到2.0**：当前3.0可能导致单次advantage过大。GRPO标准advantage也在±3.75范围但那是通过group std归一化得到的，BOK的3.0是人为截断。
2. **BOK_TAU_INIT=0.9 (更保守开始)**：从更接近uniform的温度开始，减少早期集中度。
3. **adaptive kl**：如果kl_loss>0.05(阈值)则动态提升kl_coef，类似PPO中的KL target。

## 六、BOK-GRPO可行性评估

### 6.1 Steps 1-50的"健康期"数据

在崩溃之前，BOK-GRPO和Standard GRPO的reward几乎完全一致：
- Step 40: BOK overall=0.844 vs GRPO overall=0.849 (差异<0.6%)
- Step 50: BOK overall=0.820 vs GRPO overall=0.818 (BOK略优)

**结论**：BOK-GRPO在参数正确时，学习能力与Standard GRPO相当。

### 6.2 理论优势

BOK-GRPO的softmax集中机制在reward有方差时提供更清晰的信号：
- 对于"部分正确"的组(some pass, some fail)，BOK能更准确地放大最好的trajectory
- 对于Standard GRPO，归一化advantage平等对待好和一般的trajectory

### 6.3 风险评估

修复后的BOK-GRPO风险点：
1. **kl_coef=0.05 + BOK集中advantage**：可能导致学习稍慢(更保守)，但稳定性有保障
2. **DAPO_FILTER=0 + drgrpo fallback**：低方差组使用Dr.GRPO方式处理，避免信号丢失
3. **TAU_FINAL=0.5**：不会过度集中，保持一定探索

### 6.4 最终判断

> **BOK-GRPO在修正参数后值得重新实验。** 关键修复是kl_coef从0.01提升到0.05（匹配GRPO），DAPO_FILTER关闭。结合已添加的安全监控机制，预期可以实现稳定训练。但不建议期望BOK-GRPO显著超越Standard GRPO，因为当前任务(StepCount)的主要瓶颈是视觉point准确性而非探索/利用平衡。
